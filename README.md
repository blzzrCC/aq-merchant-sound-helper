# 暗区鉴宝

通过**拾取音效**识别《暗区突围：无限》战地行商「神秘物资」中的物品，辅助购买决策。

行商的货物在购买前**不显示图片**，唯一线索是拖动物品时播放的拾取音效。本工具采集系统输出音频，与本地声音库比对，给出候选物品。

---

## 一、合规边界（先看这段）

本工具**只做一件事**：读取操作系统混音器的输出（WASAPI Loopback），与本地声音库比对，把结果推送到手机。

**不做的**：不读写游戏内存、不注入进程、不覆盖游戏画面、不截图、不 OCR、不代替你操作、不修改任何游戏文件。

工具实质是「替你更快地听，替你查一张静态价目表」。但官方条款措辞宽泛（"以任何方式优化或改变游戏"），**残余风险不为零，是否使用由你自行判断**。详见 `docs/暗区鉴宝-技术方案-v0.2.md` §2 C2.1。

## 三、三步工作流

### 第 1 步 — 采样

双击 `1-采样.cmd`，或：

```bash
python tools/record_inbox.py --device "扬声器"
```

装好耳机、**固定系统音量**，进游戏拖动物品。每听到一次拾取音，工具自动切出并存入 `data/library/_inbox/`。

> **关键**：采样与使用必须用**同一副耳机、同一音量**。音频模型对录制链路的音染极度敏感，换设备会让识别失效。

查看可用设备：`python tools/record_inbox.py --list`

### 第 2 步 — 打标

不玩游戏时运行：

```bash
python tools/label_inbox.py
```

逐个试听样本，归档到音效类：

- **回车** 播放 / 重播
- **数字** 选已有音效类
- **n** 新建音效类（会问类名 + 对应物品名）
- **s** 跳过 ｜ **d** 删除 ｜ **q** 保存退出

> **多件物品共用同一音效**时，把它们登记到**同一个音效类**下即可 —— 这正是本工具处理「共用音效」的方式。

采完一轮后建议跑一次标定：

```bash
python tools/calibrate.py
```

它输出两个关键数字：

- **共音分组率**（音效类数 / 物品数）—— 决定产品上限的核心指标。≥0.8 可识别到单件物品；0.5~0.8 输出候选集；<0.5 只能给到类别。
- **建议判定阈值** —— 由留一交叉验证算出，写入 `data/library/calibration.json`，第 3 步自动读取。

> **注意**：阈值随特征参数变化（启用 CMN 后相似度绝对尺度会变），不要手写死。

### 第 3 步 — 实时识别

```bash
python tools/match_live.py --http-port 8765
```

控制台会打印本机地址，例如 `http://192.168.1.7:8765`。  
**手机连同一个 WiFi，浏览器打开该地址**，即可实时看到识别结果。

手机页面包含：命中的音效类、候选物品列表、相似度条、其他相近音效。

```
│   ├── calibration.json  # 标定结果（calibrate.py 产出，match_live 自动读取）
│   ├── samples/<音效类>/  # 已打标样本（入库时已裁掉静音）
│   └── _inbox/           # 待打标样本
└── docs/                # 技术方案与调研报告
```

### 关于 `data/library/` —— 全部是运行时产物

该目录下的**任何文件都不进 Git**，由脚本在使用者本机生成：

| 文件 | 何时生成 |
| --- | --- |
| `library.json`、`items.json` | 首次运行打标工具时由 `aq_library.save()` 创建 |
| `calibration.json` | 运行 `tools/calibrate.py` 后创建 |
| `samples/`、`_inbox/` | 采样过程中写入 |

原因有二：这些内容**因人而异**（每个人的录音、物品命名都不同），且**采样音频属游戏素材**，不适合分发。仓库只分发代码与文档，克隆后跑一遍「安装 → 采样 → 打标」即可得到自己的库。

## 五、算法要点

1. **采集** — WASAPI Loopback 抓系统混音输出，48 kHz / 双声道。
2. **降混** — 立体声转单声道（左右差异主要来自声像，是噪声）。
3. **裁静音** — 去掉首尾静音段，只保留有效音频。实测参考素材的静音占比达 2%~76%，
   不裁会让 DTW 把静音帧对齐到有效音帧，跨时长配对分数被系统性压低。
   以 10ms 帧 RMS 相对峰值 -45dB 为判据，首尾各留 20ms 保护瞬态。
4. **重采样** — 统一到 16 kHz。
5. **峰值归一** — 消除音量差。
6. **特征** — 64 维 Mel 对数频谱。
7. **CMN（倒谱均值归一化）** — 逐 Mel 维减去时间轴均值，吸收设备频响造成的加性偏移。
   实测可把 EQ 倾斜 4dB/oct 下的自相似从 0.669 拉回 0.948，top-1 由 11/15 恢复到 15/15。
8. **匹配** — 余弦代价 DTW，带 Sakoe-Chiba 带宽限制。
   带宽下限自动覆盖两段帧数之差，否则终点不可达、会返回伪 0 相似度。
9. **判定** — 相似度 ≥ 阈值才算命中。阈值随特征参数变化，由标定工具产出，不要写死。

自测（不依赖游戏，验证建库→匹配闭环）：

```bash
python tools/selftest.py
```

标定判定阈值 + 输出共音分组率（需已有样本，每类建议 ≥ 2 条）：

```bash
python tools/calibrate.py
```

素材质量审计（去重 / 可分性 / 跨链路鲁棒性）：

```bash
python tools/ref_audit.py --dir data/library/samples/<音效类> --matrix --perturb
```

## 六、调参

| 症状        | 调整                                       |
| --------- | ---------------------------------------- |
| 漏检（拖了没反应） | `record_inbox.py --threshold 0.008` 调低   |
| 误检（没拖也触发） | `--threshold 0.02` 调高，或 `--noise-mult 6` |
| 识别不准      | 同一物品多采几条；确认采样与使用设备一致                     |
| 命中率低      | 跑 `tools/calibrate.py` 重标阈值；或临时 `match_live.py --min-sim 0.7` |
| 音头被削掉     | `aq_dsp.trim_silence(pad_ms=50)` 加大保护段 |
| 静音没裁干净    | `aq_dsp.trim_silence(thresh_db=-35)` 抬高判据 |

## 七、常见问题

**Q：采不到音频？**  
确认默认播放设备正确、Windows 音频服务运行中。运行 `python tools/record_inbox.py --list` 看是否有 loopback 端点。

**Q：声音库为空能匹配吗？**  
不能。`match_live.py` 会直接报错退出。必须先完成采样 + 打标。

**Q：手机打不开网页？**  
确认手机与电脑在同一 WiFi；Windows 防火墙可能拦截 8765 端口，需放行。

**Q：识别显示多件物品怎么办？**  
说明该音效被多件物品共用。按方案 §5.5，结合**占用格数**与**标价档位**自行收敛（这部分需要人眼判断，工具不读游戏画面）。
