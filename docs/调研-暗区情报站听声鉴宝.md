# 调研报告 — 暗区情报站「行商听声鉴宝练习」

| 项 | 内容 |
|---|---|
| 调研对象 | https://aqtwwx.net/listen-treasure |
| 站点名称 | 暗区情报站（暗区突围无限工具站） |
| 日期 | 2026-09-30 |
| 调研目的 | 验证《暗区鉴宝》项目的玩法定义、技术可行性与数据结构 |
| 调研方式 | 公开页面抓取 + 前端打包代码静态分析 + 静态资源可访问性验证 |

---

## 1. 结论摘要

1. **玩法定义得到确认。** 战地行商的「神秘物资」在购买前不显示图片，玩家只能靠**拖动物品时的拾取音效**分辨藏品。项目假设成立。
2. **音效类数量已被验证为有限集合：15 种。** 且音效文件公开可访问，ID 为数字 `1`~`15`。
3. **发现一条关键业务规则**，来自站点内置 FAQ 原文，直接决定产品设计（见 §4）。
4. **音效资源格式已取得硬参数**：48 kHz / 16 bit / 立体声 / 约 576 ms。可直接用于确定离线窗口与特征参数。
5. **存在一个已上线的同类产品**，但定位是**练耳练习工具**，与「实战实时辅助」并不冲突（见 §6）。

## 2. 产品形态

站点提供三种练习模式：

| 模式 | 说明 | 状态 |
|---|---|---|
| 行商鉴宝 | 1:1 复刻行商玩法，凭拾取音效挑出最值钱的藏品 | 已上线 |
| 声音图鉴 | 逐一试听全部拾取音效，建立「声音 ↔ 藏品」对应认知 | 已上线 |
| 限时挑战 | 限定时间内连续鉴宝 | 开发中 |

**版本策略**：体验版（免登录，商品更少更简单，成绩不计入排行）／完整版（登录 + 兑换码或赞助会员，1:1 完整行商场景，成绩计入排行）。

**玩法规则要点**：

- 初始现金 60W~120W 随机
- 每局限制最大购买件数
- 拖动货物试听拾取音效，点击或按 F 键加入购物车
- 提供「情报」功能，可花钱探查物品信息
- 结算时成绩 = 所购藏品的实际价值之和
- 品质分档：白 / 蓝 / 紫 / 金 / 红

**平台限制**：仅支持电脑端浏览器，需要 ≥1200px 窗口宽度同时展示背包、行商与商品区。

## 3. 技术实现

| 项 | 内容 |
|---|---|
| 前端框架 | Vue 3 + Vite + ant-design-vue，SPA |
| 页面路由 | `/listen-treasure`（懒加载视图组件） |
| 后端接口 | `/api/basic/v1/` 下的鉴宝相关端点，按需下发音效清单与映射表（完整端点清单不复述） |
| 音效资源 | 站点自托管静态资源，按数字编号命名，前端直接加载（路径模板不复述） |
| 相关模块 | 另有一个行商音效专题页，以及搜索容器音效模块 |

> **说明**：本节仅记录架构结论，不提供可直接复制的接口地址与资源路径模板。调研目的是验证玩法定义，不是提供抓取指引。

### 3.1 数据结构（从前端代码还原）

```js
// /dzi-open/sounds 返回：音效 ID 列表
[{ soundId }, ...]

// /dzi-open/codex 返回：音效 → 藏品 的映射
[{
  soundId,
  items: [{ itemId, ... }, ...]
}, ...]
```

前端逻辑：遍历 codex，建立 `Map<soundId, itemId[]>`，用于判定「同一声音对应哪些藏品」。这与本方案 §4 设计的 `mapping.json` **结构完全一致**，可视为外部佐证。

### 3.2 音效资源格式（实测）

| 参数 | 值 |
|---|---|
| 采样率 | 48000 Hz |
| 位深 | 16 bit |
| 声道 | 2（立体声） |
| 时长 | 0.576 s |

> 48 kHz 与 Windows WASAPI Loopback 的默认混音采样率一致，采集侧无需重采样。0.576 s 的时长意味着事件窗口应设为 **600 ms 量级**，与本方案原先预估的 550 ms 基本吻合，现修正为 650 ms（含前后保护段）。

### 3.3 另一条线索：游戏内部音效命名规则

站点某模块暴露了游戏搜索容器音效的资源路径，从中可读出稳定的命名规则：

| 维度 | 规则 |
|---|---|
| 目录划分 | 医疗用品 / 大金 / 杂物 / 武器 / 装备 / 食品 —— 共六个大类 |
| 文件名前缀 | `Item_*` 为装备类，`Prop_*` 为道具类 |
| 文件名后缀 | `_Up` 表示「拾取」动作 |

> 具体资源路径不复述 —— 那属于游戏资源结构，不适合公开记录。

**这条信息的价值**：命名规则显示，**拾取音效在游戏资源层面就是按物品模板分配、而非按单个物品分配** —— 这正是「多件物品共用同一音效」的技术根因。

同时它给出了六个搜索容器音效大类：医疗用品 / 大金 / 杂物 / 武器 / 装备 / 食品。注意：这是**搜索容器**的音效，与行商拖拽音效不是同一套，但**分类思路可能一致**。

## 4. 最关键的一条情报

站点内置 FAQ 中有一条问答，原文如下：

> **问：同一种声音一定是同一件藏品吗？**
>
> **答：不一定。游戏中多件藏品可能共用同一种拾取音效，因此听到相同的声音时，还需要结合<u>占用格数、档位价、货物名称和情报</u>综合判断。**

这条规则的影响是根本性的：

1. **它证实了本方案 §2 的 C1 约束**（音效与物品非一对一），并给出了权威依据。
2. **它指出纯音效识别是不够的** —— 必须引入其他可见信息做交叉过滤，才能把候选集收敛到可用范围。
3. 它明确了四个可用于交叉过滤的维度：

| 维度 | 性质 | 可否自动获取 |
|---|---|---|
| 占用格数 | 物品在背包/商品区占几格 | 可（视觉）但需读画面，与合规约束冲突 |
| 档位价 | 商品区显示的标价档位 | 可（视觉）同上 |
| 货物名称 | 商品区文字 | 可（OCR）同上 |
| 情报 | 游戏内探查功能 | 不可，需玩家手动操作 |

> **重要推论**：四个维度中有三个需要读取游戏画面，而本方案已确立「不采集画面」的合规约束（见技术方案 §1.3）。这意味着**候选集收敛必须依靠玩家的手动输入**，而非自动读取。
>
> 应对方向：工具输出候选集后，提供**一键筛选**交互（如"占 4 格"、价格档位切换），由玩家自行点选过滤。这把合规风险转移到人工操作上，同时保留了收敛能力。

## 6. 竞品定位分析

| 维度 | 暗区情报站·听声鉴宝 | 本项目《暗区鉴宝》 |
|---|---|---|
| 形态 | 网页练习工具（模拟环境） | 桌面实时辅助工具（真实游戏） |
| 使用场景 | 不玩游戏时练耳 | 玩游戏时实时提示 |
| 数据来源 | 后端下发 + 站点实录音效 | 本地 JSON + 用户自录音效 |
| 核心价值 | 训练玩家的耳朵 | 直接给出答案 |
| 合规风险 | 无（纯网页，不接触游戏） | 低但非零（独立窗口 + 音频回环） |
| 依赖 | 需联网、需登录解锁完整版 | 完全本地、离线可用 |

**判断**：两者不构成直接竞争。参考站是**练习场**，本项目是**实战外挂**（信息层面的，非功能层面的）。

但由此引出一个**战略岔路**，必须由用户决策：

- **路线一（实战辅助）**：在真实游戏里实时识别并提示。价值最高，但存在反作弊残余风险，且候选集收敛需要玩家手动配合。
- **路线二（练耳工具）**：复刻参考站形态，做桌面离线版声音图鉴 + 练习。**零合规风险**，但差异化不足（参考站已免费提供）。
- **路线三（本地图鉴 + 实战双模式）**：核心是本地音效指纹库，两种前端共用。练耳模式零风险，实战模式按需开启。

> **倾向性意见**：路线三。核心资产是「音效 → 藏品」的本地库与匹配引擎，两种使用形态共享同一套底层。用户可先以练耳模式熟悉并验证数据质量，再决定是否启用实战模式。

## 7. 调研边界声明

本次调研遵守以下边界：

- 仅分析**公开可访问**的页面与静态资源；
- 遇到后端 API 返回 403（`请求参数不完整`）后**未尝试绕过**其访问控制；
- 仅下载 **1 个**音效样本用于解析格式参数，**未批量抓取**站点整理的音效素材；
- 站点音效素材系第三方「实录」整理，**不建议直接用于产品**，原因有二：一是版权归属不明，二是实录文件带有录制设备音染，与用户本机不一致，会直接损害模型精度（见技术方案 §2 C4）。

> 正确做法仍为用户**在本机自行录制**，这既是版权上最干净的选择，也是技术上必须的选择。
